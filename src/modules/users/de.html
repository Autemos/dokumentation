User Management

⚠️Nur für Administratoren — Der Bereich User Management ist ausschliesslich für Administratoren zugänglich. Nur Benutzer mit administrativen Berechtigungen können Benutzer einladen, bearbeiten, deaktivieren, löschen, Projekte zuweisen und Rollen verwalten. Dies gewährleistet eine sichere und zentralisierte Zugriffskontrolle innerhalb der gesamten Autemos Plattform.

Das User Management Menü ist der zentrale Administrationsbereich zur Verwaltung aller Benutzer innerhalb von Autemos.

Was Administratoren können

  • Benutzer erstellen und einladen
  • Benutzerkonten verwalten
  • Projektzugriffe zuweisen
  • Projektrollen konfigurieren
  • Benutzeraktivitäten überwachen
  • Plattformberechtigungen steuern

Benutzer löschen

Administratoren können Benutzer dauerhaft aus dem System entfernen.

⚠️Wichtige Hinweise — Beim Löschen eines Benutzers werden Berechtigungen sofort entfernt. Historische Test-Zuweisungen können erhalten bleiben, und Audit-Logs können weiterhin Referenzen speichern.

Reset Link

Mit der Aktion Reset Link erzeugen Administratoren für einen Benutzer einen Link, über den dieser ein neues Passwort setzt. Der Link wird als Antwort angezeigt, sodass er auch dann weitergegeben werden kann, wenn der Mailversand nicht möglich ist; zusätzlich wird er per Mail versandt, sofern die Mail-Anbindung konfiguriert ist (siehe Notification Settings).

  • Der Link gilt 24 Stunden. Ältere Links desselben Benutzers verfallen, sobald ein neuer erzeugt wird.
  • Für eingeladene Benutzer, die noch kein Passwort gesetzt haben, funktioniert die Aktion ebenfalls.
  • Nicht möglich ist sie für Konten, die von einem angebundenen Verzeichnisdienst (DAI) verwaltet werden, und für Konten, die ein Administrator gesperrt hat.
  • Reset-Links werden nie im Backend-Log ausgegeben — auch nicht, wenn der Mailversand scheitert.
Verwaltung

Anmeldung & Passwort vergessen

Benutzername und Passwort

  • Der Benutzername beim Login ist unabhängig von Gross-/Kleinschreibung: „Admin“, „ADMIN“ und „admin“ melden denselben Benutzer an. Angezeigt wird weiterhin die Schreibweise, die bei der Anlage gewählt wurde.
  • Dieselbe Regel gilt für die Eindeutigkeitsprüfung beim Einladen: Ein Name, der sich nur durch Gross-/Kleinschreibung von einem bestehenden unterscheidet, wird als Dublette abgewiesen.
  • Bestehen in einer Installation bereits Konten, die sich nur durch die Schreibweise unterscheiden, meldet der exakt geschriebene Name das passende Konto an; ein mehrdeutiger Name wird abgewiesen.
  • Das Passwort bleibt gross-/klein-empfindlich.

Forgot Password

Auf der Login-Seite führt der Link Forgot Password? zur gleichnamigen Seite. Ein nicht angemeldeter Benutzer setzt dort sein Passwort selbst zurück:

  • E-Mail-Adresse eintragen und Send Reset Link wählen.
  • Die Seite bestätigt immer neutral: „If an account exists for this email address, we have sent a link to reset your password. The link is valid for 30 minutes.“ Sie verrät nicht, ob ein Konto zur Adresse existiert.
  • Der Link in der Mail öffnet die Seite zum Setzen des neuen Passworts. Dort listet Password requirements die Regeln der Passwortrichtlinie (siehe Security).
  • Nach dem Speichern erscheint „Password updated. You can now sign in with your new password.“ und die Anmeldeseite öffnet sich.
  • Der Link ist zeitlich begrenzt und einmalig. Ein ungültiger, abgelaufener oder bereits benutzter Link führt zur Meldung „This password reset link is invalid, has expired or has already been used. Please request a new one.“ mit dem Link Request a new link.
  • Die Anzahl der Anfragen ist je E-Mail-Adresse und je Netzwerkadresse begrenzt; bei Überschreitung erscheint „Too many requests. Please wait a few minutes and try again.“
  • Für Konten, die nicht zurückgesetzt werden dürfen (verzeichnisverwaltet oder gesperrt), wird kein Link versandt — die Antwort bleibt trotzdem neutral.
  • Der Kontoinhaber wird nach dem Zurücksetzen per Mail benachrichtigt, dass sein Passwort geändert wurde.
💡Alle System-Mails (Passwort-Reset, Passwort geändert, Einladung, Admin-Reset-Link) laufen über die in den Global Settings konfigurierte Mail-Anbindung. Ist keine Mail-Anbindung konfiguriert, bleibt der Admin-Weg über Reset Link.
Rechte

Rollen & Rechte

Autemos prüft bei jeder projektbezogenen Aktion, ob der angemeldete Benutzer im betroffenen Projekt die nötige Rolle hat. Die Prüfung gilt für alle Wege (Oberfläche, Recorder, Worker, API) gleichermassen.

Viewer

Ein Benutzer mit der Projektrolle Viewer darf ein Projekt nur lesen. Jede schreibende Aktion — etwa Secrets oder Auth-Konfigurationen anlegen und ändern, die Xray-Verknüpfung oder das Projekt-Mapping ändern, Testdaten, Workflows oder Recorder-Sitzungen verändern — wird abgewiesen. Der Benutzer sieht dann eine Fehlermeldung bzw. die Seite „Forbidden“; es gibt keinen Erfolgshinweis, und es wird nichts verändert. Lesen bleibt vollständig möglich, auch die Seite der Projekt-Settings.

Nicht-Mitglieder

Wer angemeldet ist, aber keine Rolle im Projekt hat, erhält für Daten dieses Projekts weder Lese- noch Schreibzugriff. Das gilt auch für die Testdaten (Easy-Datensätze und ihre Zeilen), Recorder-Sitzungen, Live-Ansichten und die Steuerung laufender Ausführungen. Für unbekannte oder fremde Ressourcen gibt es keine Auskunft, ob sie existieren. Ohne Anmeldung sind diese Bereiche nicht mehr erreichbar.

Weitere Regeln

  • Recorder: Beim Speichern von Page Objects aus einer Recorder-Sitzung werden nur Objekte des Projekts dieser Sitzung geschrieben. Verweist die Anfrage auf ein anderes Projekt, wird sie abgewiesen, bevor etwas gespeichert wird.
  • Healing: Die Validierung gegen eine Worker-Sitzung verlangt Leserecht im Projekt; für eine fremde oder unbekannte Sitzung wird sie abgewiesen und liefert keine Ergebnisse.
  • Projekt-Admins: Ein Projekt-Admin ohne globale Admin-Rolle kann alle Reiter der Projekt-Settings nutzen. Mitglieder ohne Admin-Rolle können dort nichts ändern. Den Klartext eines Secrets anzuzeigen bleibt globalen Administratoren vorbehalten; der Knopf wird Projekt-Admins deshalb nicht angeboten.
  • API-Schlüssel: An einigen Stellen sind API-Schlüssel nicht erlaubt: Projekt-Secrets anlegen, ändern, löschen oder ihren Wert anzeigen, persönliche Secrets, Zeitpläne anlegen, Benutzerdaten ändern sowie einzelne Dashboard-, Such- und AI-Recorder-Funktionen. Dort antwortet Autemos mit einer klaren Meldung („API-Schlüssel sind an diesem Endpunkt nicht erlaubt“) statt mit einem Serverfehler.
💡Wer eine Aktion nicht ausführen darf, braucht eine höhere Projektrolle — Administratoren weisen sie unter Projekte & Rollen zu.
