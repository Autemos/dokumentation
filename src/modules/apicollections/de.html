Erste Schritte

API Collections

API Collections bieten einen zentralen Ort, um API-Definitionen in Autemos zu importieren, zu verwalten, auszuführen und wiederzuverwenden.

Statt jeden API-Request manuell zu konfigurieren, lässt sich eine bestehende OpenAPI-/Swagger-Spezifikation importieren. Autemos wandelt die Spezifikation in eine API Collection um, welche die verfügbaren Endpoints und deren relevante Konfiguration enthält.

API Collections zentral verwalten — importierte Spezifikation mit Runtime Environment und Endpoint-Liste.

Drei Verwendungsarten

Direkt ausführen

Endpoints direkt aus der API Collection heraus ausführen und validieren — ohne Test Workflow.

Als Workflow-Schritt

Eine komplette API Collection als einzelnen Schritt innerhalb eines Test Workflows ausführen.

Einzelne Endpoints

Beim Konfigurieren eines API Request Nodes einzelne Endpoints aus einer Collection auswählen.

Dadurch lässt sich API-Testing direkt mit Browser- und Mobile-Automatisierung im selben Test Workflow verbinden. Autemos unterstützt Web-, Mobile- und API-Testing bereits innerhalb eines einzigen Workflows.

Import

Eine API Collection importieren

Navigieren Sie innerhalb Ihres Projekts zu API Collections und wählen Sie Import.

Unterstützte Quellen

  • File — Upload einer OpenAPI-Datei im Format .json oder .yaml
  • URL — Angabe der URL einer verfügbaren OpenAPI-Spezifikation
OpenAPI / Swagger direkt importieren — per Datei oder URL.
Import

Import-Konfiguration

Während des Imports stehen die folgenden Optionen zur Verfügung:

EinstellungBeschreibung
OpenAPI File / URLQuelle der OpenAPI-Spezifikation
Collection nameOptionaler eigener Name für die API Collection
Operations marked as deprecatedLegt fest, wie als deprecated markierte Operationen behandelt werden
Enable schema validation for all endpointsAktiviert die Response-Schema-Validierung für alle importierten Endpoints
💡Wird kein Collection name angegeben, kann Autemos den in der OpenAPI-Spezifikation definierten Titel verwenden.
Import

Schema Validation

Die Schema-Validierung kann während des Imports für die gesamte Collection aktiviert werden.

Da OpenAPI-Spezifikationen die tatsächlichen API-Responses nicht immer präzise genug beschreiben, ist die Schema-Validierung standardmässig deaktiviert. Sie kann später auch individuell für einzelne Endpoints aktiviert werden.

💡Ein Import mit global aktivierter Schema-Validierung erzeugt häufig Fehlschläge, die keine echten Defects sind. Aktivieren Sie die Validierung gezielt dort, wo die Spezifikation verlässlich ist.
Verwaltung

Collection-Übersicht

Nach dem Import einer OpenAPI-Spezifikation erstellt Autemos die API Collection und listet die verfügbaren Endpoints auf.

Jeder Endpoint enthält Informationen aus der OpenAPI-Spezifikation:

InformationBeschreibung
MethodHTTP-Methode wie GET, POST, PUT, PATCH oder DELETE
PathPfad des API-Endpoints
OperationIn der OpenAPI-Spezifikation definierte Operation
ExpectedErwarteter HTTP-Response-Status
StatusAktueller Zustand des importierten Endpoints

Die Übersicht bietet Such- und Filteroptionen, um einzelne Endpoints schnell zu finden.

Verwaltung

Runtime Environment

Jede API Collection kann mit der Runtime-Konfiguration verbunden werden, die zur Ausführung ihrer Endpoints benötigt wird.

Application

Auswahl einer im Projekt konfigurierten Anwendung. Ohne Auswahl wird die in der OpenAPI-Spezifikation definierte Base-URL verwendet.

Default Environment

Definiert die Standardumgebung für die Ausführung der Collection, z. B. DEV / TEST / INT / PROD.

Auth Config

Auswahl einer wiederverwendbaren Authentifizierungs-Konfiguration, statt Credentials pro Request zu pflegen.

Test Data Binding

Verbindet die Collection mit einem Test Data Binding, um dynamische Testdaten während der Ausführung zu nutzen.

Damit lässt sich dieselbe Collection gegen unterschiedliche Datensätze und Umgebungen ausführen.

Verwaltung

Eine API Collection ausführen

Mit Run Collection wird die API Collection direkt ausgeführt. Autemos führt die aktivierten Endpoints der Collection mit dem konfigurierten Runtime Environment aus.

Wann verwenden

  • Eine importierte OpenAPI-Spezifikation schnell validieren
  • API-Smoke- oder Regressionstests ausführen
  • Endpoints nach API-Änderungen prüfen
  • Eine API unabhängig von einem UI-Test-Workflow validieren
💡Sie müssen keinen Test Workflow erstellen, nur um die in einer Collection enthaltenen APIs auszuführen.
Test Workflows

API Collections in Test Workflows

API Collections sind direkt in Autemos Test Workflows integriert. Damit werden APIs Teil eines End-to-End-Geschäftsprozesses, statt als isolierte API-Tests ausgeführt zu werden.

API und UI zu echten End-to-End-Tests verbinden — Browser-Schritte und API Request im selben Workflow.

Typische Abläufe

  • Browser Action → API Request → Verify Response → Browser Action
  • API Setup → Mobile Action → API Validation → Web Verification

Dies baut auf dem bestehenden Autemos-Konzept auf, Web-, Mobile- und API-Testing innerhalb eines einzigen Workflows zu kombinieren.

Test Workflows

Einzelnen API-Endpoint verwenden

Fügen Sie dem Test Workflow einen API Request Node hinzu. Der Node kann manuell konfiguriert oder aus einer bestehenden API Collection befüllt werden.

Wählen Sie dazu Choose from collection. Autemos öffnet den Dialog zur Endpoint-Auswahl.

API Request Node — „Choose from collection" öffnet die Endpoint-Auswahl.

Wählen Sie zunächst die gewünschte API Collection und anschliessend einen oder mehrere verfügbare Endpoints. Endpoints lassen sich innerhalb des Dialogs direkt durchsuchen.

API Calls direkt in Workflows übernehmen — Collection wählen, Endpoints suchen und einfügen.

Beispiel

  • GET /posts
  • POST /posts
  • GET /posts/{postId}
  • PUT /posts/{postId}
  • DELETE /posts/{postId}
Test Workflows

Automatische Request-Konfiguration

Wird ein Endpoint aus einer API Collection ausgewählt, verwendet Autemos die Informationen der importierten OpenAPI-Spezifikation, um den API Request Node zu befüllen.

Je nach Endpoint-Definition kann dies umfassen:

  • HTTP-Methode
  • URL / Endpoint
  • Authentifizierung
  • Headers
  • Request Body
  • Response-Informationen

Die Konfiguration bleibt in den Standard-Tabs des API Request Nodes verfügbar:

TabInhalt
RequestMethode und Ziel-URL
AuthAuthentifizierungs-Modus und Credentials
HeadersHTTP-Header als Key/Value-Paare
BodyRequest-Body für POST/PUT/PATCH
ResponseResponse-Handling und Response Alias
💡Die importierte Konfiguration ist ein Startpunkt — der Request kann bei Bedarf weiterhin angepasst werden.
Test Workflows

Verify Nodes automatisch erstellen

Bei der Auswahl eines Endpoints aus einer API Collection kann die Option Also create verify nodes aktiviert werden. Autemos erstellt dann zusammen mit dem API Request die passenden Verifikationsschritte.

Das reduziert den Aufwand, bereits in der API-Spezifikation definierte Validierungen manuell nachzubauen, und macht aus einer OpenAPI-Definition schneller einen ausführbaren API-Test.

Die generierte Verifikation lässt sich anschliessend im Test Workflow über die reguläre Verify Response Funktionalität anpassen.

Anwendung

API und UI kombinieren

Einer der zentralen Vorteile von API Collections ist die Möglichkeit, API-Operationen mit UI-Automatisierung zu verbinden.

Beispielablauf

1

Einen Kunden über eine API erstellen

2

Die zurückgegebene Customer ID speichern

3

Die Anwendung im Browser öffnen

4

Nach dem neu erstellten Kunden suchen

5

Den Kunden über die UI ändern

6

Einen weiteren API-Endpoint aufrufen

7

Prüfen, dass das Backend die aktualisierten Informationen enthält

So lässt sich der komplette Geschäftsprozess testen, ohne API- und UI-Automatisierung auf verschiedene Tools oder Test Suites aufzuteilen.

Anwendung

Typische Anwendungsfälle

API Regression Testing

Eine OpenAPI-Spezifikation importieren und die komplette API Collection ausführen, um die verfügbaren Endpoints zu validieren.

API Setup für UI-Tests

Über API-Requests den benötigten Testzustand herstellen, bevor Browser- oder Mobile-Interaktionen starten.

Backend Verification

Einen Geschäftsprozess über die UI durchführen und anschliessend per API-Request den resultierenden Backend-Zustand prüfen.

Hybrid End-to-End Testing

Browser-, Mobile- und API-Interaktionen innerhalb eines einzigen Test Workflows kombinieren.

Wiederverwendbare API-Definitionen

API-Definitionen zentral über API Collections pflegen, statt dieselben Requests in mehreren Workflows manuell zu konfigurieren.

Anwendung

Best Practices

  • APIs wenn möglich aus der massgeblichen OpenAPI-Spezifikation importieren
  • API Collections als zentrale Quelle für wiederverwendbare API-Definitionen nutzen
  • Authentifizierung zentral konfigurieren, statt Credentials über Requests hinweg zu duplizieren
  • Environments verwenden, um hartcodierte URLs zu vermeiden
  • Test Data Bindings für dynamische und wiederverwendbare API-Tests einsetzen
  • Run Collection für API-Regression und Smoke-Testing verwenden
  • Einzelne API Request Nodes verwenden, wenn APIs Teil eines grösseren End-to-End-Prozesses sind
  • Automatische Verify-Node-Erstellung aktivieren, wenn die OpenAPI-Spezifikation verlässliche Response-Definitionen enthält
  • API-Setup und -Validierung mit UI-Automatisierung kombinieren, um End-to-End-Tests schneller und robuster zu machen
