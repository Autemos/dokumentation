Code Template Management

⚠️Eingeschränkter Zugriff — Nur für Testarchitekten / Administratoren — Das Modul ist für fortgeschrittene Benutzer (Testarchitekten, Framework Engineers, Administratoren) vorgesehen. Fehlerhafte Änderungen an Templates können direkten Einfluss auf den generierten Automation Code in allen Projekten haben.

Das Modul Code Template Management ermöglicht es Testarchitekten und Administratoren, die Templates zu definieren und zu verwalten, welche von Autemos für die automatische Codegenerierung verwendet werden.

Code Template Management — zentrale Verwaltung aller Codegenerierungs-Templates pro Sprache und Framework.

Grundlage für

Code Generation Engine

Dynamische Generierung von Automation Code.

KI-gestützte Generierung

Basis für AI-erzeugten Automation Code.

Framework-Exportsystem

Framework-spezifischer Code-Export.

Anstatt statischen, vordefinierten Code zu generieren, erstellt Autemos den Automatisierungscode dynamisch auf Basis konfigurierbarer Templates. Dadurch kann der generierte Code vollständig an interne Coding Standards, Framework-Strukturen, Architekturvorgaben, Naming Conventions und Enterprise Best Practices angepasst werden.

Zweck

  • Generierten Automation Code standardisieren
  • Mehrere Programmiersprachen unterstützen
  • Verschiedene Automatisierungsframeworks unterstützen
  • Generierte Teststrukturen anpassen
  • Unternehmensweite Coding Standards einhalten
  • Templates an interne Frameworks anpassen

Konfiguration

Sprache & Framework Auswahl

Bevor Templates bearbeitet werden können, müssen Benutzer eine Programmiersprache und ein Automatisierungsframework auswählen. Dadurch entstehen framework-spezifische Template-Konfigurationen.

Haupttemplate-Typen

Das System unterstützt verschiedene Template-Kategorien:

pageobject

Templates für wiederverwendbare PageObject-Klassen.

test

Templates für ausführbare Testklassen.

Diese Templates definieren die grundlegende Struktur des generierten Automation Codes.

💡Jede Kombination aus Sprache + Framework hat ihre eigene Template-Konfiguration — z. B. unterscheidet sich ein Java/Selenium-PageObject grundlegend von einem TypeScript/Playwright-PageObject.
Template Editor

Template Editor

Der Template Editor definiert die allgemeine Codestruktur, die während der Codegenerierung verwendet wird — Imports, Klassenstrukturen, Konstruktoren, Methoden, Feldinjektionen und Variablen-Placeholder.

Template Editor — Klassenstruktur, Konstruktoren und Variablen-Placeholder für die Codegenerierung.

Main Template

Das Main Template steuert die generierte Klassenstruktur:

PageObject Templates

Struktur wiederverwendbarer PageObjects.

Testklassen-Templates

Struktur ausführbarer Testklassen.

Template-Variablen

Templates unterstützen dynamische Platzhaltervariablen — diese werden während der Codegenerierung automatisch ersetzt:

VariableVerwendung
${className}Name der generierten Klasse
${fields}Felder-Block (Field Annotations)
${methods}Methoden-Block (Interaction Methods)
${packageName}Package- bzw. Namespace-Name

Constructor Template

Definiert, wie Konstruktoren generiert werden. Beispielhafte Anwendungsfälle:

  • WebDriver Injection
  • Dependency Injection
  • Framework-Initialisierung
  • PageFactory-Initialisierung

Beschreibungsfeld & Speichern

Das Description-Feld dokumentiert den Zweck des Templates zur besseren Wartbarkeit. Die Aktion Save Template speichert die aktualisierte Template-Konfiguration — Änderungen wirken sich unmittelbar auf zukünftigen generierten Code aus.

Node Templates

Node Templates

Node Templates definieren, wie Workflow-Nodes in Automation Code übersetzt werden. Jede Workflow-Aktion kann abhängig von Sprache, Framework und Architektur unterschiedlichen Code generieren.

Node Templates — Definition der Code-Generierung pro Workflow-Aktion (Click, Assertion, Navigation, …).

Unterstützte Node-Typen

Assertion

Verifikationen und Validierungen.

Click

Klick-Interaktionen.

Navigation

URL-Navigation und Routing.

Validation

Datenvalidierungen.

API Calls

HTTP-Aufrufe.

Wait Conditions

Synchronisation und Waits.

Template-Variablen

Node Templates unterstützen dynamische Platzhalter, die automatisch aus den Workflow-Daten befüllt werden:

VariableBeschreibung
${varName}Variablen-Name
${methodCall}Methodenaufruf
${value}Eingabewert
${url}Ziel-URL
${duration}Wartezeit / Timeout
${expected}Erwarteter Wert
${actual}Tatsächlicher Wert

Beispiel

Ein Assertion-Node kann beispielsweise als Template definiert sein:

assertEquals(${expected}, ${actual});

Während der Generierung wird daraus konkreter Code:

assertEquals("Success", resultText);
Methods & Fields

Methods & Field Types

Der Bereich Methods & Field Types definiert Feldannotationen, generierte Feldstrukturen und wiederverwendbare Interaktionsmethoden. Dadurch können generierte PageObjects framework-spezifischen Konventionen folgen.

Methods & Field Types — Templates für Feldannotationen und wiederverwendbare Methoden.

Eingabefelder.

Field Annotation Templates

Dieser Bereich definiert, wie UI-Elemente im generierten Code dargestellt werden:

  • Selenium-Annotationen
  • Playwright-Locators
  • Appium-Mobile-Selektoren

Wiederverwendbare Methoden

Das System unterstützt wiederverwendbare Interaktionsmethoden:

MethodeVerwendung
clickKlick auf ein Element
typeTexteingabe
clearFeld leeren
getValueWert auslesen

Jede Methode kann benutzerdefinierte Implementierungslogik, framework-spezifisches Verhalten und Enterprise Utilities enthalten.

Hinweise auf fehlende Templates

Das System markiert unvollständige Template-Definitionen mit dem Hinweis „Missing Template". Dadurch können Architekten unvollständige Framework-Konfigurationen schnell identifizieren.

Edit- & Delete-Aktionen

Jedes Methodentemplate unterstützt Edit und Delete — dadurch ist eine vollständige Verwaltung wiederverwendbarer Automation-Methoden möglich.

Configuration

Configuration Import / Export

Der Configuration-Bereich ermöglicht Unternehmen, Template-Konfigurationen zu exportieren, zu importieren und zwischen Umgebungen zu migrieren.

Configuration Import / Export — Template-Konfigurationen für Backup, Migration und Team-Synchronisation.

Export Configuration

Exportiert die aktuelle Template-Konfiguration für:

  • Backups
  • Migrationen
  • Versionierung
  • Austausch zwischen Teams

Import Configuration

Importiert zuvor exportierte Template-Konfigurationen — nützlich für:

  • Onboarding
  • Framework-Rollouts
  • Synchronisation mehrerer Umgebungen
