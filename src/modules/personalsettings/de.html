Persönliche Einstellungen

Das Modul Persönliche Einstellungen ermöglicht Benutzern die Verwaltung ihrer eigenen Kontoinformationen und persönlichen Zertifikatskonfigurationen. Es ist über den Benutzer-Avatar oben rechts in der Plattform erreichbar.

Persönliche Einstellungen — erreichbar über den Benutzer-Avatar oben rechts.

Funktionen

Persönliche Profilinformationen

Übersicht der eigenen Kontodetails.

Persönliche Runtime-Zertifikate

Verwaltung individueller mTLS-Zertifikate.

Persönliche Zertifikatsquellen

Eigene File-System- oder Vault-Quellen.

mTLS-Client-Zertifikate

Sichere Client-Authentifizierung gegenüber geschützten Anwendungen.

Verfügbare Aktionen

  • Persönliche Einstellungen öffnen
  • Profilinformationen anzeigen
  • Persönliche Zertifikate verwalten
  • Persönliche Runtime-Quellen verwalten
  • Von der Plattform abmelden

Zertifikate & Quellen

Zertifikate

Die Sektion Zertifikate verwaltet persönliche Runtime-Zertifikatskonfigurationen. Zertifikate werden getrennt von gemeinsam genutzten Projektkonfigurationen gespeichert.

Sie ermöglicht

  • Speicherung persönlicher mTLS-Zertifikate
  • Konfiguration persönlicher Runtime-Dateiquellen oder Vault-Quellen
  • Nutzung individueller Zertifikate für sichere API-Kommunikation
  • Tests von mTLS-geschützten Anwendungen mit persönlicher Identität
Add Certificate Source — Runtime-Quelle für persönliche Zertifikate hinzufügen.

Persönliche Quellen

Persönliche Quellen definieren benutzerspezifische Runtime-Speicherorte für Zertifikate und sichere Dateien.

Hilfreich wenn

  • Benutzer keine globalen/shared Zertifikatsquellen verwenden sollen
  • Persönliche Vault-Zugangsdaten benötigt werden
  • Teamunabhängige Zertifikatsverwaltung erforderlich ist

Zertifikate & Quellen

Persönliche Zertifikate

Persönliche Zertifikate werden für die sichere Client-Authentifizierung gegenüber mTLS-geschützten Anwendungen verwendet. Zertifikate referenzieren eine Runtime-Quelle und können optional mit einem Passwort geschützt werden.

Unterstützte Zertifikatformate

  • PKCS#12 (.p12 / .pfx)

Zertifikatskonfiguration

ParameterBeschreibung
NameName des Zertifikatsprofils
BeschreibungOptionale Beschreibung
Certificate SourceReferenz auf die Runtime-Quelle
Certificate TypeZertifikatsformat
Certificate FileHochgeladene Zertifikatsdatei
PasswordOptionales Zertifikatspasswort
Allowed OriginsErlaubte Ziel-Domains

Allowed Origins

Allowed Origins beschränken die Verwendung eines Zertifikats auf definierte Zielsysteme. Beispiel: https://example.com. Dies erhöht die Sicherheit, indem Zertifikate nur für freigegebene Domains verwendet werden dürfen.

⚠️Sicherheitshinweis — Zertifikate und Secrets werden sicher zur Laufzeit verarbeitet.

Best Practices

  • Separate Zertifikate pro Umgebung verwenden
  • Allowed Origins möglichst einschränken
  • Persönliche Zertifikate nicht teilen
  • Zertifikate mit Passwort schützen
  • Zertifikate regelmässig rotieren
Account

Security & Passwort ändern

Im Reiter Security der Personal Settings ändern Sie Ihr Passwort im Bereich Change Password.

Felder

FeldBeschreibung
Current PasswordIhr aktuelles Passwort als Nachweis.
New PasswordDas neue Passwort. Darunter zeigt die Liste Password requirements die Regeln (siehe unten).
Confirm New PasswordWiederholung des neuen Passworts.

Jedes Feld hat ein Augensymbol, mit dem die Eingabe sichtbar gemacht wird. Fehler erscheinen direkt am betroffenen Feld: falsches aktuelles Passwort, abweichende Bestätigung, ein Verstoss gegen die Passwortregeln oder ein neues Passwort, das dem aktuellen entspricht.

Passwortregeln

Standardmässig gilt: mindestens 8 und höchstens 128 Zeichen, mindestens ein Buchstabe und mindestens eine Ziffer („At least 8 characters, including a letter and a number“). Unter New Password steht die Liste Password requirements mit einem Eintrag je Regel. Jeder Eintrag zeigt per Text Met oder Not met, ob die Regel erfüllt ist, und aktualisiert sich mit jedem Tastendruck. Dieselbe Liste erscheint auf der Seite zum Zurücksetzen des Passworts.

Nach dem Ändern

  • Alle anderen Sitzungen des Benutzers werden ungültig; sie müssen sich neu anmelden.
  • Die aktuelle Sitzung bleibt angemeldet.
  • Die Änderung erscheint als Sicherheitsereignis im Audit Log — ohne die Passwörter selbst.

Hilfe

Guided Tours

Geführte Touren erklären Oberflächen Schritt für Schritt. Eine Tour hebt jeweils ein Element hervor und erklärt es in einem kleinen Dialog.

Getting started

Im Avatar-Menü steht zwischen Settings und Logout der Eintrag Start guided tour. Die Tour Getting started führt durch den Rahmen der Anwendung.

  • Next, Back und Done führen durch die Schritte; ein Zähler zeigt den Fortschritt.
  • Mit Skip tour, der Escape-Taste oder einem Klick ausserhalb endet die Tour.
  • Die Tour startet nie automatisch. Ob Sie sie gesehen oder übersprungen haben, merkt sich Autemos pro Benutzer auf dem Server; ungesehene Touren tragen am Menüeintrag das Badge „New“. Sie lässt sich beliebig oft neu starten.

Feature-Touren

Grössere Bereiche haben eine eigene Tour, die Sie mit dem Knopf Tour im Kopf der Seite starten. Aktuell gibt es die Recorder tour (Recorder) und die Workflow tour (Workflow-Liste, in allen Reitern, für alle Rollen).

  • Feature-Touren sind interaktiv: Manche Schritte warten darauf, dass Sie das hervorgehobene Element anklicken („Click … to continue“) oder einen Dialog öffnen.
  • Sie gehen über Seiten und Dialoge hinweg. Mit Back stellt die Tour den vorherigen Zustand wieder her; ein dafür geöffneter Dialog (z. B. Add Session) wird wieder geschlossen.
  • Ein Klick ausserhalb beendet die Tour nicht, damit Sie während der Tour mit der Seite arbeiten können. Verlassen Sie den Bereich des Features, endet die Tour.
  • Ist ein Element nicht vorhanden, erklärt die Tour den Schritt zentriert oder überspringt ihn.
⚠️Eine Tour startet nie etwas selbst — weder eine Session noch eine Aufnahme noch eine Ausführung. Im Schritt „Start Session“ der Recorder tour ist der Knopf zwar hervorgehoben, ein Klick startet aber nichts; ein Hinweis im Dialog („Session start is paused while a tour is running…“) erklärt das. Beenden oder überspringen Sie die Tour, dann starten Sie die Session wie gewohnt. Die Tour erklärt ausserdem, wo eine Aufnahme an der Toolbar gestoppt wird.

Unter Logout zeigt das Avatar-Menü einen Fussbereich mit den Angaben, die der Support für Rückfragen braucht.

EintragBeschreibung
Frontend-BuildBauzeit der Oberfläche im Format „Build TT.MM.JJJJ HH:MM UTC - sha7“ (sha7 = die ersten sieben Zeichen der Code-Version; fehlt sie, z. B. bei lokalen Builds, entfällt dieser Teil).
Backend-BuildDieselbe Angabe für den Server.
Support-IDEine Kennung pro Browser-Tab; ein neuer Tab hat eine neue ID. Sie lässt sich kopieren.

Die Support-ID wird mit jeder Anfrage an den Server mitgesendet. So findet der Support zu Ihrer Meldung die passenden Server-Logeinträge.
