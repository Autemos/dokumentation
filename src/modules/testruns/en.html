Test Run Overview

Test Runs

The Test Run Overview is the central entry point for all executed workflows and historical runs. It gives teams a view of execution health and enables quick navigation to individual runs or workflow details.

When to use

  • Monitor the overall health of your automation suite
  • Identify which workflows are failing or becoming unstable
  • Navigate to a specific execution for investigation
  • Filter runs by status, environment, or time range

The overview is divided into two tabs: Tests (aggregated workflow-level analysis) and Runs (overview of individual executions).

Tests Tab

The Tests tab focuses on workflow stability and historical execution quality. It helps users identify:

  • Unstable workflows and flaky automation
  • Execution trends over time
  • Long-term quality indicators
Tests tab — workflow-level analysis with pass rates, duration, and stability indicators.

Flaky label

Tests detected as unstable are automatically marked with a Flaky label. The flaky score is calculated based on pass/fail transitions, inconsistent execution behavior, and unstable execution history — allowing teams to quickly identify automation that requires stabilization.

Workflow status

StatusDescription

BrokenWorkflow continuously failed across multiple executions

Runs Tab

The Runs tab displays all individual workflow executions. This view focuses on:

  • Results and status of individual executions
  • Environments and browsers or devices used
  • Runtime analysis and duration
  • Healing visibility per execution

Healing indicator

A purple heart icon next to a run indicates that self-healing was applied during the execution. The number indicates how many healing operations took place.

Examples

Run Details Page

Test Runs

The Run Details Page provides a complete step-by-step execution view for a single workflow run. It is the primary tool for debugging, root cause analysis, and healing investigation.

When to use

  • Debug a failed execution to identify the root cause
  • Review each workflow step and its result
  • Validate screenshots to assess UI state during execution
  • Verify self-healing behavior and repaired selectors
Run Details Page — complete step-by-step execution report for a single workflow run.

Execution summary

The top section of the Run Details Page displays a high-level summary of the execution.

  • Workflow name and execution timestamp
  • Total duration and overall execution status
  • Browser or device used
  • Execution environment
  • Overall pass rate for this run

Test Case execution flow

All workflow steps are displayed chronologically, providing complete visibility into execution behavior.

Each step includes:

  • Node type and action description
  • Execution duration per step
  • Execution result (passed / failed)
  • Step screenshots
  • Technical details for debugging

Screenshots

Execution screenshots are automatically captured during workflow execution. They help users visualize workflow progress, investigate failures, validate UI behavior, and analyze execution context. Screenshot visibility and scaling can be adjusted directly in the report.

Healing details

When self-healing was applied during execution, the report displays detailed healing information for each repaired step.

Healing details — original selector, repaired selector, and confidence score for each healed step.
FieldDescription
Healed StepThe workflow step that required automatic repair
OldOriginally failing selector
NewAutomatically repaired selector
ConfidenceReliability score of the healing result

Healing confidence

The confidence score indicates how reliable the automatic repair is. Higher confidence scores represent stronger selector similarity, more reliable healing candidates, and greater execution stability going forward.

⚠️ Always review healing results before promoting workflows to production. A low confidence score may indicate that the repaired selector requires manual validation.

Common use cases

The most common scenarios for using the Test Runs module — and which view is used for each.

Workflow stability analysis

Use the Tests view to monitor overall automation quality.

  • Identify workflows marked as flaky
  • Monitor pass rates across the entire automation suite
  • Analyze long-term automation quality trends
  • Prioritize stabilization work by flaky scores

Execution investigation

Use the Runs view to review individual executions.

  • Review results of a specific run
  • Analyze runtime behavior and duration
  • Investigate environment-specific issues
  • Compare results across different browsers or environments

Failure debugging

Use the Run Details Page for in-depth investigation of failed executions.

  • Review screenshots to understand the UI state at the time of failure
  • Inspect failed steps and their technical error output
  • Analyze stack traces for root cause analysis
  • Verify whether self-healing solved or masked the issue

Healing validation

Use healing indicators and healing details to monitor and validate automatic recovery.

  • Monitor automatic recovery behavior across runs
  • Validate repaired selectors before promoting workflows
  • Analyze workflow resilience over time
  • Identify workflows that rely too frequently on healing

Best Practices

Recommendations to get the most out of the Test Runs module.

  • Monitor flaky workflows regularly — detect instability before it reaches production
  • Investigate broken workflows immediately — continuous failure signals a fundamental problem
  • Review healing results before workflow promotion — low confidence scores require manual validation
  • Use execution history instead of isolated failures — a single failure may be noise; a pattern is a signal
  • Analyze screenshots when debugging — visual context is faster than reading logs
  • Filter executions by environment when troubleshooting — isolate environment-specific issues
  • Use the run ID to communicate with team members about specific executions
  • Set up status-based filtering to focus daily reviews on Failed and Broken workflows
