Test Runs

Das Test Runs-Modul bietet zentralisierte Transparenz über automatisierte Testausführungen, Ausführungshistorie, Workflow-Stabilität und Debugging-Informationen. Es gibt Teams alles, was sie benötigen, um ihre automatisierten Test-Workflows zu überwachen, zu untersuchen und zu verbessern.

Was das Modul bietet

  • Ausführungsgesundheit über alle Workflows hinweg überwachen
  • Workflow-Stabilität und Pass-Rate-Trends analysieren
  • Einzelne Fehler mit schrittweisen Traces untersuchen
  • Flaky Automation erkennen, bevor sie Probleme verursacht
  • Detaillierte Ausführungs-Traces mit Screenshots prüfen
  • Automatische Self-Healing-Aktivität und Ergebnisse überprüfen

Test Run Overview

Test Runs

Die Test Run Overview ist der zentrale Einstiegspunkt für alle ausgeführten Workflows und historischen Ausführungen. Sie gibt Teams einen Überblick über den Ausführungszustand und ermöglicht eine schnelle Navigation zu einzelnen Läufen oder Workflow-Details.

Wann verwenden

  • Überwachung der allgemeinen Gesundheit Ihrer Automations-Suite
  • Identifizierung welche Workflows fehlschlagen oder instabil werden
  • Navigation zu einer bestimmten Ausführung zur Untersuchung
  • Filtern von Läufen nach Status, Environment oder Zeitraum

Die Übersicht ist in zwei Tabs unterteilt: Tests (aggregierte Analyse auf Workflow-Ebene) und Runs (Übersicht einzelner Ausführungen).

Tests-Tab

Der Tests-Tab konzentriert sich auf Workflow-Stabilität und historische Ausführungsqualität. Er hilft Benutzern dabei zu identifizieren:

  • Instabile Workflows und Flaky Automation
  • Ausführungstrends über die Zeit
  • Langfristige Qualitätsindikatoren
Tests-Tab — Analyse auf Workflow-Ebene mit Pass Rates, Dauer und Stabilitätsindikatoren.

Flaky Label

Als instabil erkannte Tests werden automatisch mit einem Flaky-Label markiert. Der Flaky-Wert wird auf Basis von Pass/Fail-Wechseln, inkonsistentem Ausführungsverhalten und instabiler Ausführungshistorie berechnet — sodass Teams schnell Automation identifizieren können, die Stabilisierung erfordert.

BrokenWorkflow schlug über mehrere Ausführungen hinweg kontinuierlich fehl

Healing-Indikator

Ein violettes Herzsymbol neben einem Lauf zeigt an, dass Self-Healing während der Ausführung angewendet wurde. Die Zahl gibt an, wie viele Healing-Operationen stattgefunden haben.

Beispiele

IndikatorBedeutung
💜 1Ein Selector oder Workflow-Schritt wurde automatisch geheilt
💜 3Drei Healing-Operationen erfolgten während dieser Ausführung

Dies bietet sofortige Transparenz über Workflow-Resilienz und automatisches Wiederherstellungsverhalten, ohne den vollständigen Ausführungsbericht öffnen zu müssen.

Run Details Page

Test Runs

Die Run Details Page bietet eine vollständige schrittweise Ausführungsübersicht für eine einzelne Workflow-Ausführung. Sie ist das primäre Werkzeug für Debugging, Ursachenanalyse und Healing-Untersuchung.

Wann verwenden

  • Debugging einer fehlgeschlagenen Ausführung zur Ursachenfindung
  • Prüfung jedes Workflow-Schritts und seines Ergebnisses
  • Validierung von Screenshots zur Beurteilung des UI-Zustands während der Ausführung
  • Überprüfung von Self-Healing-Verhalten und reparierten Selektoren
Run Details Page — vollständiger schrittweiser Ausführungsbericht für einen einzelnen Workflow-Lauf.

Ausführungszusammenfassung

Der obere Bereich der Run Details Page zeigt eine übergeordnete Zusammenfassung der Ausführung an.

  • Workflow-Name und Ausführungszeitstempel
  • Gesamtdauer und übergeordneter Ausführungsstatus
  • Verwendeter Browser oder Gerät
  • Ausführungs-Environment
  • Gesamt-Pass-Rate für diesen Lauf

Test Case Ausführungsfluss

Alle Workflow-Schritte werden chronologisch angezeigt und bieten vollständige Transparenz über das Ausführungsverhalten.

Jeder Schritt enthält:

  • Node-Typ und Aktionsbeschreibung
  • Ausführungsdauer pro Schritt
  • Ausführungsergebnis (bestanden / fehlgeschlagen)
  • Schritt-Screenshots
  • Technische Details zum Debugging

Screenshots

Ausführungs-Screenshots werden während der Workflow-Ausführung automatisch erfasst. Sie helfen Benutzern, den Workflow-Fortschritt zu visualisieren, Fehler zu untersuchen, UI-Verhalten zu validieren und den Ausführungskontext zu analysieren. Sichtbarkeit und Skalierung der Screenshots können direkt im Bericht angepasst werden.

Healing-Konfidenz

Der Konfidenzwert gibt an, wie zuverlässig die automatische Reparatur ist. Höhere Konfidenzwerte repräsentieren stärkere Selector-Ähnlichkeit, zuverlässigere Healing-Kandidaten und grössere Ausführungsstabilität in Zukunft.

⚠️ Überprüfen Sie Healing-Ergebnisse immer, bevor Sie Workflows in die Produktion übernehmen. Ein niedriger Konfidenzwert kann darauf hinweisen, dass der reparierte Selector manuelle Validierung erfordert.

Häufige Anwendungsfälle

Die häufigsten Szenarien für die Nutzung des Test Runs-Moduls — und welche Ansicht jeweils verwendet wird.

Workflow-Stabilitätsanalyse

Verwenden Sie die Tests-Ansicht, um die allgemeine Automationsqualität zu überwachen.

  • Als Flaky markierte Workflows identifizieren
  • Pass Rates über die gesamte Automations-Suite überwachen
  • Langfristige Automationsqualitätstrends analysieren
  • Stabilisierungsarbeit nach Flaky-Werten priorisieren

Ausführungsuntersuchung

Verwenden Sie die Runs-Ansicht, um einzelne Ausführungen zu prüfen.

  • Ergebnisse eines bestimmten Laufs prüfen
  • Laufzeitverhalten und Dauer analysieren
  • Umgebungsspezifische Probleme untersuchen
  • Ergebnisse über verschiedene Browser oder Environments vergleichen

Fehler-Debugging

Verwenden Sie die Run Details Page für eine tiefgehende Untersuchung fehlgeschlagener Ausführungen.

  • Screenshots prüfen, um den UI-Zustand beim Fehler zu verstehen
  • Fehlgeschlagene Schritte und deren technische Fehlerausgabe prüfen
  • Stack Traces für Ursachenanalyse analysieren
  • Prüfen, ob Self-Healing das Problem gelöst oder verdeckt hat

Healing-Validierung

Verwenden Sie Healing-Indikatoren und Healing-Details, um die automatische Wiederherstellung zu überwachen und zu validieren.

  • Automatisches Wiederherstellungsverhalten über Läufe hinweg überwachen
  • Reparierte Selektoren validieren, bevor Workflows übernommen werden
  • Workflow-Resilienz über die Zeit analysieren
  • Workflows identifizieren, die zu häufig auf Healing angewiesen sind

Best Practices

Empfehlungen, um das Beste aus dem Test Runs-Modul herauszuholen.

  • Flaky Workflows regelmässig überwachen — Instabilität erkennen, bevor sie die Produktion erreicht
  • Broken-Workflows sofort untersuchen — kontinuierliches Fehlschlagen signalisiert ein grundlegendes Problem
  • Healing-Ergebnisse vor der Workflow-Übernahme prüfen — niedrige Konfidenzwerte erfordern manuelle Validierung
  • Ausführungshistorie statt isolierter Fehler verwenden — ein einzelner Fehler kann Rauschen sein; ein Muster ist ein Signal
  • Screenshots beim Debugging analysieren — visueller Kontext ist schneller als das Lesen von Logs
  • Ausführungen beim Troubleshooting nach Environment filtern — umgebungsspezifische Probleme isolieren
  • Die Lauf-ID verwenden, um mit Teammitgliedern über bestimmte Ausführungen zu kommunizieren
  • Statusbasierte Filterung einrichten, um tägliche Reviews auf Failed- und Broken-Workflows zu fokussieren
💡 Das Test Runs-Modul bietet vollständige Transparenz über Workflow-Ausführungsqualität, Laufzeitverhalten und Automationsstabilität — von übergeordneten Analysen bis hin zu detailliertem Ausführungs-Debugging.
