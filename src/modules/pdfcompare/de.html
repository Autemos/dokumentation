PDF Compare

PDF Compare ermöglicht die automatisierte Validierung generierter oder heruntergeladener PDF-Dokumente innerhalb eines Autemos Test Workflows.

Ein PDF kann zentral als Baseline-Dokument hinterlegt und später in einem Workflow ausgewählt werden. Während der Ausführung erfasst Autemos das tatsächliche PDF und vergleicht es mit der gewählten Baseline.

Was verglichen wird

Text

Erkennt geänderte, fehlende oder zusätzliche textliche Inhalte.

Werte

Erkennt Abweichungen bei numerischen Werten im PDF.

Layout

Erkennt visuelle und positionelle Unterschiede über einen pixelbasierten Vergleich.

Dynamische Inhalte lassen sich über Exclusion Zones für visuelle Bereiche und Ignore Patterns für variablen Text behandeln. Damit bleiben auch Dokumente stabil validierbar, die wechselnde Daten, Kennzeichen, QR-Codes oder generierte Referenznummern enthalten.

PDF Compare eignet sich für Rechnungen, Kontoauszüge, Versicherungsdokumente, Verträge, Bestätigungen, Reports und weitere generierte Geschäftsdokumente.

PDF Baselines

PDF Baselines sind zentral verwaltete Referenzdokumente, die vom PDF-Compare-Node im Workflow verwendet werden.

Navigieren Sie im Projekt zu PDF Baselines, um die verfügbaren Referenzdokumente einzusehen. Die Übersicht zeigt unter anderem:

  • Name der Baseline
  • Aktuelle Version
  • Anzahl Seiten
  • Dateigrösse
  • Datum der Aufzeichnung beziehungsweise des Uploads

Eine Baseline kann von mehreren Test Workflows genutzt werden. Das vermeidet separate Referenzdateien in jedem Workflow und schafft eine kontrollierte Quelle für den Dokumentvergleich.

Baselines

Baseline-Versionen

Baselines sind versioniert. Ein Test Workflow kann je nach benötigtem Testaufbau die aktuelle Version oder eine ausgewählte Baseline-Version verwenden.

Ist Current gewählt, folgt der Workflow automatisch späteren Neuaufzeichnungen derselben Baseline. Das ist nützlich, wenn sich das freigegebene Referenzdokument ändert, die Workflow-Konfiguration aber unverändert bleiben soll.

💡Spätere Neuaufzeichnungen laufen über Record New Version auf derselben Baseline, nicht über einen erneuten Upload.

Vergleichsarten

Vergleichsarten

Die einzelnen Prüfungen adressieren unterschiedliche Aspekte eines Dokuments und lassen sich getrennt aktivieren.

Seitenanzahl

Prüft, ob Baseline und tatsächliches Dokument dieselbe Seitenanzahl enthalten. Das ist eine schnelle strukturelle Prüfung, bevor einzelne Inhalte bewertet werden.

Text- und Wertevergleich

Autemos extrahiert den PDF-Text und erkennt geänderte, fehlende oder zusätzliche Inhalte. Numerische Werte wie Preise, Summen, Daten, Mengen oder Kontowerte sind in diesem Vergleich enthalten.

Text kann pro Seite und über das gesamte Dokument geprüft werden. Beide Prüfungen sind unabhängig konfigurierbar.

Visueller und Layout-Vergleich

Für die visuelle Validierung rendert Autemos die PDF-Seiten und vergleicht sie auf Pixelebene. Damit werden Layout-Änderungen erkannt, etwa verschobene Elemente, veränderte Abstände, fehlende Komponenten oder Formatierungsunterschiede.

Render DPI steuert die Renderauflösung. Visual tolerance definiert, wie viele abweichende Pixel noch als gleich akzeptiert werden.

Vergleichsarten

Two-Stage Gating

Ist Two-Stage Gating aktiviert, führt Autemos den visuellen Vergleich erst aus, nachdem der konfigurierte Textvergleich übereingestimmt hat.

Das kann unnötige Pixelvergleiche vermeiden, wenn ein Dokument bereits auf inhaltlicher Ebene fehlschlägt.

Dynamische Inhalte

Exclusion Zones für den visuellen Vergleich

Generierte PDFs enthalten häufig Werte, die sich zwischen Ausführungen berechtigterweise ändern. PDF Compare bietet dafür getrennte Mechanismen für dynamische visuelle Bereiche und für variablen Text.

Exclusion Zones maskieren ausgewählte rechteckige Bereiche während des Pixelvergleichs. Sie eignen sich für wechselnde bild- oder positionsbasierte Inhalte wie:

  • Daten und Zeitstempel
  • QR-Codes oder Barcodes
  • Generierte Dokument- oder Rechnungsnummern
  • Dynamische Kopfzeilen, Stempel oder Signaturen
Zonen wirken ausschliesslich auf den visuellen Vergleich. Textunterschiede im maskierten Bereich schlagen weiterhin fehl und müssen separat über Ignore Patterns behandelt werden.

Zonen werden auf der betreffenden PDF-Seite konfiguriert.

Eine Exclusion Zone für einen dynamischen visuellen Bereich definieren.
Dynamische Inhalte

Ignore Patterns für den Textvergleich

Ignore Patterns kennzeichnen variablen Text, der den Vergleich nicht fehlschlagen lassen soll.

Verwenden Sie den Marker @ignore innerhalb des stabilen umgebenden Textes, um den dynamischen Teil zu kennzeichnen, zum Beispiel:

EinstellungBeschreibung
PatternUmgebender Text mit @ignore für den variablen Teil, etwa Buchungsnummer: @ignore Rückforderung
PagesKommagetrennte Seitenzahlen. Leer bedeutet: gilt für alle Seiten

Mehrere Patterns können derselben PDF-Compare-Konfiguration hinzugefügt werden.

💡Es werden keine regulären Ausdrücke geschrieben. Das Backend erzeugt den passenden Ausdruck aus dem angegebenen Muster.

Auswertung

Ergebnis im Test Report

Das Ergebnis von PDF Compare wird direkt im Test-Run-Report angezeigt.

Die Zusammenfassung zeigt den Gesamtstatus sowie den Status der konfigurierten Prüfungen, zum Beispiel:

  • Page Count
  • Text per Page
  • Full Document Text
  • Visual Difference

Das verglichene Dokument bleibt als Test-Run-Artefakt verfügbar. Schlägt eine Prüfung fehl, lässt sich die detaillierte Differenzansicht zur weiteren Analyse öffnen.

PDF-Compare-Ergebnis innerhalb des Test-Run-Reports.
Auswertung

Detaillierte Differenzansicht

Die Detailansicht stellt Referenz- und tatsächliches PDF nebeneinander dar. Unterschiede werden in beiden Dokumenten direkt hervorgehoben, sodass geänderte Inhalte und Layout-Bereiche schnell lokalisierbar sind.

Die erkannten Unterschiede lassen sich durchblättern und die Ansicht nach Vergleichsart filtern. Damit sind textliche Änderungen von visuellen Layout-Unterschieden unterscheidbar.

Erkannte PDF-Unterschiede nebeneinander analysieren.

Anwendung

Best Practices

  • Ein freigegebenes Geschäftsdokument mit klarem, stabilem Namen als Baseline verwenden
  • Current nur einsetzen, wenn Workflows späteren Baseline-Versionen automatisch folgen sollen
  • Nur die Vergleichsarten aktivieren, die für das jeweilige Dokument erforderlich sind
  • Exclusion Zones für dynamische visuelle Bereiche und Ignore Patterns für variablen Text verwenden
  • Die visuelle Toleranz niedrig halten und die Differenzansicht prüfen, bevor eine geänderte Baseline akzeptiert wird
